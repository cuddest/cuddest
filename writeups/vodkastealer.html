ClickFix / VodkaStealer — Endpoint Hunt & Service Hijacking

Summary

The investigation started with a suspected browser/CAPTCHA-based compromise and evolved into an endpoint-centric hunt using Windows Security and Sysmon telemetry. The strongest evidence ultimately showed a malicious PowerShell payload execution on PAYOPS-WS-04 under NEXTGEN\n.hesham, followed by targeted service discovery of DataSyncPro, manipulation of the DataSync Pro directory, execution of a malicious Sync.exe as SYSTEM, suspicious LSASS access from rundll32.exe, and a SYSTEM-level PowerShell reverse shell to 165.245.213.184:4444. The attacker then performed domain reconnaissance and established multiple forms of scheduled-task persistence.

Key conclusion: The malicious executable identified in the service-hijacking question was Sync.exe. The strongest C2 evidence is the SYSTEM PowerShell reverse shell to 165.245.213.184:4444.

DataSyncPro setup observed earlier

A unquoted service path vulnerability is a Windows privilege-escalation issue that happens when a Windows service's executable path contains spaces but isn't enclosed in quotes.
Simple example:
Suppose a service is configured to run:

C:\Program Files\My App\service.exe

Because the path isn't quoted, Windows can interpret the spaces ambiguously.

Windows may try possible executable paths such as:

C:\Program.exe
C:\Program Files\My.exe
C:\Program Files\My App\service.exe

If an attacker can write to one of the earlier locations they could potentially place a malicious executable there, which could turn into a privelage escalation if these locations run as NT AUTHORITY\SYSTEM for example.
