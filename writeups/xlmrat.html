XLMRat — PCAP Hunt & Malware Analysis

Scenario:

this lab provides is a simulation of a compromised machine that been flagged due suspicious network traffic, we have a PCAP file to analyze and answer the questions.

Questions:

  1. The attacker successfully executed a command to download the first stage of the malware. What is the URL from which the first malware stage was installed?

The first that comes to mind here is to filter by HTTP:

The filter got us down to 4 packets, checking the first one, we can see that the compromised machine done a GET request to the attacker server to download a txt file named xlm.txt.

extracting this file from Wireshark ( File -> Export Objects -> HTTP ), we get the obfuscated VBScript dropper the attacker used for fileless malware execution. It systematically concatenates an array of string fragments to dynamically reconstruct a malicious PowerShell command, evading basic static analysis. Upon assembly, it spawns a hidden, non-interactive shell process (cmd.exe) that launches PowerShell with restriction bypassing flags (-ExecutionPolicy Bypass, -WindowStyle Hidden). The deobfuscated payload utilizes Net.WebClient.DownloadString to fetch a remote script—disguised as an image file (mdm.jpg) from 45.126.209.4:222—and immediately executes it in memory using Invoke-Expression (IEX), bypassing disk-based detection mechanisms entirely.

http://45.126.209.4:222/mdm.jpg

  1. By analyzing the malicious scripts, two payloads were identified: a loader and a secondary executable. What is the SHA256 of the malware executable?

extracting the downloaded image, i first ran a fast ckeck on the file to see what it is actually hiding:

┌──(cuddest㉿cuddest)-[~/Downloads]
└─$ file mdm.jpg         

mdm.jpg: Unicode text, UTF-8 (with BOM) text, with very long lines (65514), with CRLF line terminators

This was a huge red flag, image usually are binary data not Unicode text.

peeking more inside to see the first characters:

┌──(cuddest㉿cuddest)-[~/Downloads]

└─$ head -c 100 mdm.jpg

$Content = @'

$hexString_bbb = "4D_5A_90_00_03_00_00_00_04_00_00_00_FF_FF_00_00_B8_00_00_00_

Hex encoded variable ! with an eye catching two first bytes 4D 5A.
A fast search online confirmed that these are the magic bytes for Windows/DOS executable files.

The smart step to do next is to extract the variable content and save it into an exe file, the get the sha256 hash using sha256sum

cat mdm.jpg | grep -oP '(?<=hexString_bbb = ")[0-9A-F_]+' | tr -d '_' | tr -d '\n' | xxd -r -p | sha256sum

1eb7b02e18f67420f42b1d94e74f3b6289d92672a0fb1786c30c03d68e81d798

  1. What is the malware family label based on Alibaba?

Searching the new exe file we have now on VirusTotal, exactly in the Detection section, we find the malware family based on Alibaba.

asyncrat
  1. What is the timestamp of the malware's creation?

I used the objdump tool which is simple and good to deal with binaries, using the -p to get the header and grep the date:

TZ=UTC objdump -p malware.exe | grep "Time/Date"

NOTE: it has to be in UTC, i got at first the answer but it did not work until i searched online and figured out that the answer must be in UTC.
