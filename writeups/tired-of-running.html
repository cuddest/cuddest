Tired of Running

This one turned into a chain of several small bugs that only became useful when combined.

Recon

The site had a login page that asked only for a System Handle. There was no password. After logging in, the main feature was a search box that accepted a file path and returned file information.

The source archive, Player.zip, explained the application architecture. One Go application exposed three servers:

8000  public pages
5000  internal /query and /upload
5002  /verify

There was also a second container called flagserver on an internal-only network. The credential lived in /opt/vault/credentials.dat with permissions 0400 owned by root.

Bug 1: The Length Field Wraps

The first bug was in the protocol used by the frontend to communicate with the internal query endpoint. The input length was encoded as uint16, which can only represent values from 0 to 65535.

If I supplied 65536 + N bytes, the encoded length wrapped around and became simply N. That meant I could control how the backend split the remaining stream and smuggle attacker-controlled values into the column and table fields.

Bug 2: Free Login Plus SQL Injection

The backend eventually constructed a query like:

SELECT * FROM %s WHERE %s='%s';

There was a filter for single quotes, but it applied only to the value. The column and table names were assumed to be trusted. Because Bug 1 let me control those fields, I could inject SQL through them.

For the login step I used a column expression equivalent to 1=1--, which transformed the query into a condition that matched everything.

Bug 3: Reading the Root Credential With YARA

The YARA execution was running as root, so I could use a rule to test whether a particular character appeared at a specific offset in the protected file. For every character position I submitted 16 rules, one for each possible hexadecimal character. After 64 positions I had recovered the full credential.

Bug 4: Turning GET Into POST

The flag server required a POST request containing the credential. The curl functionality only performed GET requests. The user_agent field was a real input and libcurl copied it directly into the HTTP headers, so I could inject CRLF characters and break the generated request into two requests on the same connection.

osq\r\n
Host: flagserver:5001\r\n
\r\n
POST / HTTP/1.1\r\n
Host: flagserver:5001\r\n
Content-Length: 64\r\n
\r\n
<credential>

The flag server accepted the credential, generated the temporary claim path, and I could finally use the normal GET path to retrieve the flag.

The interesting part was how little any individual bug achieved on its own. It was basically four small mistakes that were designed to fit together.
